### New finding not in any outline: the D-test redness is the gate-breaker

`cargo test --no-fail-fast` is currently failing on `surface_docs_audit`,
which breaks the standing gate the outline itself declares mandatory.
This outranks all Wave B/C work.

Root cause of the 283-vs-367 D1 failure: `parse_tools()` in
`tests/surface_docs_audit.rs` reads `#[tool(` lines and then scans
forward for `pub async fn <name>`, but in `src/mcp/mod.rs` roughly 84
tool methods have doc comments or multi-line macro invocations between
the attribute and the fn such that the forward scan associates the macro
with the wrong fn (or the fn-name extraction yields an empty name).
The count the registry itself reports (`mcp-tools`) is 367. The test
needs a robust parse (see fix in P0 below) — NOT a doc edit to 283.

Also observed while auditing: `#[tool(` exists only in
`src/mcp/mod.rs` (367 occurrences, 0 elsewhere), which the fixed test
can rely on for a fast, deterministic count.
