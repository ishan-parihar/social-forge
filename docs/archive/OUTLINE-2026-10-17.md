## Standing notes (tracked, not scheduled)

- **P6.1–P6.3 (LinkedIn/Facebook/Instagram cookie ports)**: stay
  REJECTED on evidence — re-evaluate only if a scraping provider is ever
  shown to work where the API path cannot.
- **B12 ceiling**: Linux Chromium cookie decrypt deliberately not
  implemented (Firefox/Zen plaintext import + explicit paste work).
  Upgrade path: PBKDF2-SHA1 `saltysalt` v10/v11 AES-128-CBC decrypt
  (`ponytail:` note at `browser_cookies.rs:64`).
- **WA Cloud inbound inbox**: webhook messages/statuses are parsed and
  trace-logged only — "an inbox table lands with the first consumer
  that needs them" (`api/whatsapp_webhook.rs:4`). Keep until a consumer
  exists.
- **Cosmetic**: streamable-HTTP `/mcp` advertises `serverInfo: rmcp`
  (identity is macro-owned by `#[tool_handler]`). Not worth overriding
  while the macro owns capabilities advertisement.
- **Ponytail ceilings** (deliberate, documented in-code with upgrade
  paths; fix only on evidence): media-sniff 64 KiB head
  (`api/media.rs:52`), rate-limit trusting XFF (`api/rate_limit.rs:155`),
  `key_hash` seq scan (`auth/middleware.rs:79`), stale writer-lock probe
  (`db/mod.rs:100`), `scheduled_at` wrap defeats index (`db/queries.rs:1415`),
  queryId bundle-scan cap 12 (`x_queryids.rs:20`), TikTok first-page-only
  lookup (`tiktok.rs:738`), Threads carousel no child-poll (`threads.rs:265`),
  telegram peer-bucket cap 4096 + 2x tail over-fetch
